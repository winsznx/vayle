# Services

Four offchain services keep Vayle's week running and tell the owner when something needs a person. Settlement never depends on any of them. Every transaction they send calls a function anyone can call, and none of them holds an admin role. With all four stopped, anyone can still finalize, settle and withdraw, from the [fallback page](../apps/fallback) or any wallet.

| Service            | What it does                                                                                                                                                                                                | Where it runs                                                 | What it needs                                                                                                                                                                                                                |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [keeper](keeper)   | Runs the weekly schedule for every market: liveness checkpoints around each close, opening each week, the first one at deploy, finalizing and settling, and the renewal batches                             | Cloudflare Worker, every minute                               | Secrets `ROBINHOOD_RPC_URL` and `KEEPER_KEY`, an account with gas only. Vars `VAYLE_MARKET`, `VAYLE_LIVENESS`, `VAYLE_CALENDAR` and `VAYLE_REGISTRY`                                                                         |
| [maker](maker)     | The team-operated maker. Bids into each renewal batch, quotes new orders mid-week, exercises what finishes in the money at its close and withdraws, in every market, and serves its bid sheet at `/v1/bids` | Cloudflare Worker, every minute, and on request               | Secrets `ROBINHOOD_RPC_URL` and `MAKER_KEY`, the account holding its USDG, each market's token and gas. Vars `VAYLE_MARKET`, `VAYLE_REGISTRY` and the `MAKER_*` pricing inputs. A custom domain for the bid sheet            |
| [watcher](watcher) | Posts an alert to a webhook, Discord's or any other, when an issuer, an oracle, the keeper, a market's listing, the calendar or an owner or guardian action needs a person                                  | Cloudflare Worker, every minute                               | Secrets `ROBINHOOD_RPC_URL`, `WATCHER_WEBHOOK_URL`, `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`. Vars `VAYLE_MARKET`, `VAYLE_LIVENESS`, `VAYLE_CALENDAR`, `VAYLE_REGISTRY` and `VAYLE_START_BLOCK`. Table `watcher_state` |
| [indexer](indexer) | Copies the market's events into Supabase and serves them as a read-only API, which the app's history panels read                                                                                            | Cloudflare Worker every minute, or a Node process on a server | Secrets `ROBINHOOD_RPC_URL`, `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`. Vars `VAYLE_MARKET` and `VAYLE_START_BLOCK`. Tables `market_events` and `indexer_state`                                                         |

The markets come from `deployments/markets.json` through `@vayle/markets`, each with its token, feed, grid, caps and the maker's volatility, and the chain ID and USDG from `deployments/robinhood-mainnet.json`, both built into each service that uses them, never from settings. At the start of every run the keeper, the maker and the watcher check each market's listing in the token registry against the file and leave out a market whose listing differs, so one bad market never stops the others. Every service builds its RPC client on `robinhoodChain` from `@vayle/chain-facts/chain`, which carries Multicall3's verified address. The keeper, the maker and the watcher pin every read in a run to one block, and reads that don't wait on each other go out together as one Multicall3 call, every market's in the same calls, so a run is a handful of RPC requests however many markets there are. The indexer reads only logs, so it has nothing to batch.

A private RPC carries its key in its URL, and viem writes URLs into its error messages. Every service logs and alerts with the text `@vayle/chain-facts/rpc-errors` makes, which keeps each URL's origin and drops its path and query.

The Workers need Cloudflare's Workers paid plan, because a run makes more subrequests and uses more CPU time than the free plan allows. [DEPLOY.md](../DEPLOY.md) has the order to deploy them in, their settings and what to fund. Each service's tests run with `pnpm --filter @vayle/<service> test` and need no network.
